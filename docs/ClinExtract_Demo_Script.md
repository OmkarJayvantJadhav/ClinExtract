# ClinExtract Demo Script

**Target Duration:** 10 Minutes
**Scenario:** End-to-end workflow from Login to checking System Health.

---

### Step 1: Login & Authentication
*   **WHAT I DO:** Navigate to the login screen and enter credentials.
*   **WHAT AUDIENCE SEES:** A clean, secure login portal with validation.
*   **INTERNALS:** JWT-based authentication, password hashing, and secure cookie storage.
*   **INTERVIEW POINT:** "Security is paramount in healthcare tech. I implemented stateless JWT authentication to ensure secure, scalable sessions without relying on server-side memory."

### Step 2: The Dashboard Overview
*   **WHAT I DO:** Arrive at the main dashboard, pointing out key metrics.
*   **WHAT AUDIENCE SEES:** A dashboard showing "Documents Processed," "Pending Reviews," and recent activity charts.
*   **INTERNALS:** Aggregation queries on the database, cached for performance.
*   **INTERVIEW POINT:** "I designed the dashboard to give clinical managers an immediate, high-level view of system throughput and pending bottlenecks."

### Step 3: Uploading a Clinical Document
*   **WHAT I DO:** Click "New Upload" and select a sample unstructured clinical note (e.g., a discharge summary).
*   **WHAT AUDIENCE SEES:** A drag-and-drop file upload interface with a progress bar.
*   **INTERNALS:** Multipart form data handling, virus scanning (simulated), and saving to secure blob storage.
*   **INTERVIEW POINT:** "I built the upload component to handle large files asynchronously, providing immediate UI feedback while the server handles the heavy lifting."

### Step 4: Asynchronous Processing State
*   **WHAT I DO:** Show the document in the queue with a "Processing" status.
*   **WHAT AUDIENCE SEES:** Real-time status updates (Queued -> Extracting -> Ready for Review).
*   **INTERNALS:** WebSockets or polling updating the UI based on a background worker queue (e.g., Redis/Celery).
*   **INTERVIEW POINT:** "To keep the UI responsive during intensive NLP tasks, I decoupled the extraction engine into background workers using a message queue."

### Step 5: Opening the Review Interface
*   **WHAT I DO:** Click on the processed document to open the Review Screen.
*   **WHAT AUDIENCE SEES:** A split-screen view: original text on the left, extracted structured data on the right.
*   **INTERNALS:** Fetching document text and associated structured entity records from the database.
*   **INTERVIEW POINT:** "This split-pane design is the core of the 'human-in-the-loop' workflow, minimizing cognitive load for the reviewer."

### Step 6: Highlighting & Entity Recognition
*   **WHAT I DO:** Hover over extracted data points (e.g., "Lisinopril 10mg") on the right.
*   **WHAT AUDIENCE SEES:** The corresponding text highlights in the original document on the left.
*   **INTERNALS:** Text offset mapping (start/end indices) generated by the NLP engine and rendered via React.
*   **INTERVIEW POINT:** "Mapping text indices allows users to instantly trace extracted data back to its source, which is critical for trust and verification."

### Step 7: Handling Low-Confidence Flags
*   **WHAT I DO:** Point out an entity flagged with a yellow warning icon (low confidence).
*   **WHAT AUDIENCE SEES:** Visual indicators for data the AI isn't 100% sure about.
*   **INTERNALS:** Confidence scoring from the NLP model driving UI conditionally.
*   **INTERVIEW POINT:** "Instead of silent failures, the system flags ambiguous text. This ensures accuracy isn't compromised by edge cases the model hasn't seen."

### Step 8: Correcting Extracted Data
*   **WHAT I DO:** Edit a flagged entity, correcting a minor error, and save it.
*   **WHAT AUDIENCE SEES:** Inline editing of the structured data form.
*   **INTERNALS:** API PUT request updating the entity record and logging an audit trail.
*   **INTERVIEW POINT:** "Every correction is logged. This not only fixes the immediate data but provides a feedback loop to retrain and improve the extraction models later."

### Step 9: Finalizing the Document
*   **WHAT I DO:** Click the "Approve & Finalize" button.
*   **WHAT AUDIENCE SEES:** Status changes to "Completed," document moves out of the review queue.
*   **INTERNALS:** Database transaction marking the document state and locking further edits.
*   **INTERVIEW POINT:** "I use database transactions here to ensure data integrity during state changes, preventing race conditions if multiple users access the same file."

### Step 10: Searching & Filtering
*   **WHAT I DO:** Go to the Data Explorer and search for all patients with a specific extracted medication.
*   **WHAT AUDIENCE SEES:** A powerful search interface returning structured results.
*   **INTERNALS:** Indexed database queries or integration with a search engine (like Elasticsearch).
*   **INTERVIEW POINT:** "This demonstrates the ultimate value of the project: turning unstructured text into a highly queryable, structured database."

### Step 11: Exporting Data
*   **WHAT I DO:** Select several finalized documents and click "Export to CSV/JSON."
*   **WHAT AUDIENCE SEES:** A file download containing the clean, structured data.
*   **INTERNALS:** Server-side generation of export files streaming back to the client.
*   **INTERVIEW POINT:** "I implemented streaming exports to handle large datasets efficiently without overwhelming server memory."

### Step 12: System Health & Logs
*   **WHAT I DO:** Navigate to the Admin/System Health dashboard.
*   **WHAT AUDIENCE SEES:** Server uptime, API latency, and a log tail.
*   **INTERNALS:** Integration with monitoring tools or custom health-check endpoints.
*   **INTERVIEW POINT:** "I built observability into the system from the start. Knowing how the application behaves in production is just as important as the features themselves."
